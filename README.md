## 项目概述

MBTI Cocktail 将 16 种 MBTI 人格类型与鸡尾酒文化结合：

- **连续强度匹配模型**：不是简单的"四字母对号入座"，而是以 0-100% 的维度强度加权计算匹配分（基酒 30% + 结构 25% + 风味 25% + 口感 10% + 场景 10%），滑杆的每一次微调都会实时影响推荐结果
- **内置 50 款鸡尾酒数据库**：覆盖金酒、伏特加、朗姆、威士忌、龙舌兰五大基酒体系，每款含完整配方、背景故事、风味标签与技法说明
- **AI 生成管线**：结构选择 → 基酒选择 → 配料组装 → 风味冲突检测 → 属性推断 → 命名生成 → 去重重试，产出真正独一无二的配方
- **暗调复古酒吧视觉**：深蓝底色 + 金色点缀，纯 CSS 实现无图片视觉方案
- **隐私优先**：无账号、无联网、无埋点，全部数据存于浏览器 `localStorage`

产品设计与算法规格详见 [PRD.md](PRD.md)。

## 核心功能

| 模块 | 功能 | 说明 |
|------|------|------|
| 🍹 智能推荐 | 四滑杆 + Top-5 推荐 | 连续强度加权评分，卡片显示匹配度，支持「换一批」无限翻牌 |
| ✨ AI 特调 | 专属配方生成 | 根据维度强度实时独创配方，含风味冲突校验，可无限重新生成 |
| 🥂 碰杯模式 | 双人合体特调 | 两人各调维度（或直选类型），混合后走 AI 管线，命名体现两人格张力（如"哈迪斯 × 阿芙洛狄忒之誓"） |
| 👅 味觉档案 | 👍/👎 反向微调 | 对喝过的酒打分，聚合为偏好向量，推荐分 ±5 小幅修正，越用越懂你 |
| ⚡ 神话命名 | 16 型神话原型 | INTJ-哈迪斯、ENFP-狄俄尼索斯……AI 命名升格为"哈迪斯之谋"式风格，可一键开关（仅影响命名，不影响算法） |
| 📚 鸡尾酒百科 | 50 款全库浏览 | 评分降序、关键词搜索、分类/技法双维筛选、🎲 随机来一杯 |
| ❤️ 收藏管理 | 一键收藏 | 经典酒与 AI 特调均可收藏，按时间倒序展示，跨会话保留 |
| 📋 复制配方 | 一键复制文案 | 材料 + 用量 + 装饰 + 技法，`file://` 打开自动降级兼容复制 |
| 🍸 个人页 | 人格酒单 + 我的吧台 | 最近 10 杯专属特调回看；收藏/经典/AI 特调/好喝/不合口味五项统计 |

## 安装步骤

### 方式一：下载即用（推荐）

1. 前往 [Releases 页面](https://github.com/YELLOWDUCK10/MBTI-Cocktail001/releases)
2. 下载最新版本资产中的 `MBTI-Cocktail-vX.X.X.html`
3. **双击打开**，即可使用

无需安装浏览器以外的任何软件；推荐 Chrome / Edge 等现代浏览器。

### 方式二：从源码构建

适用于需要修改源码或参与贡献的场景。

**环境要求**：Node.js v16 及以上（推荐 v18+），下载地址：<https://nodejs.org>

```bash
# 1. 克隆仓库
git clone https://github.com/YELLOWDUCK10/MBTI-Cocktail001.git
cd MBTI-Cocktail001

# 2. 构建单文件产物
node build.js
```

构建脚本零第三方依赖（仅用 Node 内置模块），执行后会：

1. 对酒款数据库做 **schema 校验**（必填字段 / 枚举值 / 数值范围 / 去重 / 总数），数据不合法直接阻断构建
2. 将 `src/` 下的 CSS 内联为 `<style>`、JS 按依赖序拼接内联为 `<script>`（自动剥离 ES import/export）
3. 产出 `dist/index.html`

## 使用方法

### 1. 设定你的性格

- 拖动 **E/I、S/N、T/F、J/P** 四组滑杆，精细调节倾向强度（默认 50/50 中性）
- 或点击「快速选择类型」，在 16 宫格中直选 MBTI 类型（倾向默认 75/25）

### 2. 获取推荐与 AI 特调

- 点击「查看我的鸡尾酒」进入结果页：顶部 5 款推荐按匹配度排序，卡片上的匹配度条实时反映你的维度倾向
- 点「🎲 换一批」翻看更多推荐
- 页面下方「AI 特调」会自动生成一杯专属配方，不满意可「重新生成AI特调」

### 3. 碰杯模式（双人）

1. 首页点击「🥂 碰杯模式」
2. 左右两栏各代表一位玩家：各自拖动滑杆，或点「🎯 直选类型」
3. 点击「🥂 生成合体特调」——两组人格维度混合后产出一杯独一无二的合体酒
4. 不满意可重新生成；结果可进详情页收藏

### 4. 建立味觉档案

1. 打开任意酒的详情页，在「味觉档案」区块点「👍 好喝」或「👎 不合口味」（再点一次取消）
2. 反馈会聚合为偏好向量：同基酒 / 同结构 / 同风味的酒款在后续推荐中整体小幅上浮（±5 分内）
3. 反馈数据仅存本机，可在「我的吧台」查看统计

### 5. 查阅鸡尾酒百科

- 「📚 鸡尾酒百科」页支持按**分类**（经典/热带/现代/烈酒/奶油）与**技法**（摇和/搅拌/直调等六法）筛选
- 顶部搜索框支持中文名、英文名、标签、风味模糊匹配
- 「🎲 随机来一杯」帮你告别选择困难

### 6. 收藏与个人页

- 卡片右上角心形或详情页心形一键收藏
- 个人页「🍸 人格酒单」自动收录最近 10 杯 AI 特调与合体特调，点击回看
- 「我的吧台」展示收藏数与味觉反馈统计
- 「✨ 神话命名」开关控制 AI 特调命名风格（详见[配置说明](#配置说明)）

## 配置说明

本应用为开箱即用设计，无配置文件。可调整项如下：

### 神话命名开关

个人页 → 设置 → 「✨ 神话命名」。开启后 AI 特调以 16 型神话原型命名（如 INTJ → "哈迪斯之谋"），关闭后回归"职业昵称"风格（如"战略家协奏曲"）。**仅影响命名层，不影响推荐与匹配算法。**

### 数据存储

所有数据保存在浏览器 `localStorage`，与打开文件的路径绑定，关闭后不丢失：

| 键 | 内容 |
|------|------|
| `mbti-cocktail-favorites` | 收藏（经典酒引用 + AI 酒完整对象） |
| `mbti-cocktail-gen-history` | AI 生成历史（酒名 + 完整配方 + 时间戳，兼容旧版纯名称格式） |
| `mbti-cocktail-last-state` | 上次滑块位置与 MBTI 类型 |
| `mbti-cocktail-myth-switch` | 神话命名开关（`on` / `off`） |
| `mbti-cocktail-taste` | 味觉档案偏好向量（基酒/结构/风味净计数 + 单酒反馈记录） |

**重置数据**：清空浏览器对应站点的 localStorage 即可完全重置。

> 提示：碰杯模式的双方输入为当次会话状态，不做持久化。

### 构建配置（贡献者相关）

- JS 拼接顺序由 [build.js](build.js) 中的 `JS_ORDER` 数组控制，新增源文件需在此登记依赖顺序
- 酒款数据库的枚举值、数值范围与总数校验规则也在 [build.js](build.js) 中维护

## 项目结构

```
MBTI-Cocktail/
├── build.js              # 零依赖打包脚本（schema 校验 + CSS 内联 + JS 拼接）
├── package.json          # 项目配置（仅 build 脚本）
├── src/                  # 源码（模块化 ES Module）
│   ├── index.html        # 页面结构
│   ├── style.css         # 样式（暗调复古酒吧主题）
│   ├── app.js            # 应用主逻辑（路由、交互、收藏、存储）
│   ├── engine.js         # 推荐引擎（加权评分、AI 生成、合体特调、味觉修正）
│   ├── cocktails.js      # 鸡尾酒数据库（50 款）
│   ├── mbti-profiles.js  # 16 种 MBTI 人格档案（含神话原型映射）
│   └── flavor-library.js # 风味素材库（基酒、配料、技法、冲突规则、命名词库）
├── dist/                 # 构建产物（已随仓库提交）
│   └── index.html        # 最终单文件，双击即用
├── PRD.md                # 产品需求文档
└── README.md             # 本文件
```

> `dist/index.html` 已随仓库一起提交，下载代码后无需构建即可直接使用。仅当修改 `src/` 源码后，才需要运行 `node build.js` 重新生成。

## 常见问题

**Q：`dist/index.html` 不存在？**
A：该文件已随仓库提交。若缺失，在项目根目录运行 `node build.js` 重新生成。

**Q：数据存在哪里？换浏览器还在吗？**
A：浏览器的 `localStorage`，与访问路径绑定；换浏览器或换存放路径会被视为不同站点，数据不共享。

**Q：修改源码后如何生效？**
A：改完 `src/` 下的文件后重新运行 `node build.js`，再刷新 `dist/index.html`。

**Q：点击「复制配方」没有反应？**
A：应用已内置降级复制方案（Clipboard API → execCommand），`file://` 打开同样可用。若个别浏览器安全策略拦截，可手动选中文本复制。

**Q：为什么推荐结果和朋友的"同类型"不一样？**
A：推荐基于连续维度强度而非四字母标签，滑杆位置不同结果即不同；味觉档案的 👍/👎 反馈也会带来 ±5 分内的排序修正。

## 贡献指南

欢迎通过 Issue 与 Pull Request 参与贡献。

### 贡献流程

1. Fork 本仓库并创建功能分支：`git checkout -b feat/your-feature`
2. **只修改 `src/` 下的源码**，不要手动编辑 `dist/index.html`（构建自动生成）
3. 完成后运行 `node build.js`，确保构建与数据校验通过
4. 提交并推送，发起 Pull Request，描述清楚改动内容与动机

### 提交信息规范

采用 Conventional Commits 风格：

| 前缀 | 用途 |
|------|------|
| `feat:` | 新功能 |
| `fix:` | 缺陷修复 |
| `docs:` | 文档变更 |
| `style:` | 样式调整（不影响逻辑） |
| `build:` | 构建脚本 / 打包相关 |
| `refactor:` | 重构 |

### 新增酒款数据规范

向 [src/cocktails.js](src/cocktails.js) 添加酒款时，需满足构建脚本强制校验：

- 必填字段齐全：`id`、`name`、`nameEn`、`category`、`glass`、`structure`、`baseSpirit`、`strength`、`sweetness`、`abv`、`color`、`difficulty`、`rating`、`mbtiMatch`、`description`、`story`、`method`、`methodLabel`、`ingredients`、`garnish`、`flavorNotes`、`scene`、`tags`
- 枚举合法：`structure` / `baseSpirit` / `method` / `category` / `mbtiMatch` 均限于 [build.js](build.js) 中定义的枚举集合
- 数值范围：`strength`、`sweetness` ∈ 1-5；`difficulty` ∈ 1-3；`rating` ∈ 1-5
- `id` 全库唯一；新增后如总数变化，需同步调整校验中的总数断言
